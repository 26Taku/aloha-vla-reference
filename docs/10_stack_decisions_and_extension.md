# 10 構成を選び、センサ拡張の範囲を決める

この章は07の概念・論文紹介を、研究目的に合う構成の判断へつなぐ資料です。実機で確認した収録経路、学習・推論を確認した経路、未試験の候補を区別します。対象機体・データ・計算環境が異なる場合は、必要条件を照合してください。

## 1. 基準構成と他の経路

| 層・候補 | 基準構成との違い・確認範囲 | 再検討する条件 |
|---|---|---|
| 駆動・記録：固定revisionのTrossenプラグイン＋LeRobot | 基準構成。対象AI seriesの双腕・4カメラ・v3収録を確認した | 機体、driver、必要な観測・制御が変わる |
| 元祖ALOHA／ROS／HDF5 | 未試験。ROS資産・HDF5を利用する別経路。対象となるALOHAの世代・機体対応を確認する | 既存ROS資産やHDF5データを維持する、対象機体が異なる |
| Trossenの旧LeRobotフォーク | 固定したTrossenプラグインとは別の経路。使用commitと対応するLeRobot・Datasetの版を確認する | 過去環境・データ・機能を引き継ぐ必要がある |
| 現行LeRobotへ更新 | 固定版を収録・学習の基準にしている。現行版への置換は未確認 | 必要機能が固定版にない。更新差分と再検証範囲を特定する |
| Trossen Aloha UI | 未試験。操作・記録のGUI経路。対象機体と保存形式の確認が必要 | GUI運用が要件。対象機体・出力形式・学習接続を確認する |
| Dataset：LeRobot v3 | 基準形式。収録データを08の学習・オフライン推論へ接続した | 専用実行系が別形式を要求する |
| Dataset：v1／v2 | 基準構成の新規収録はv3。v1／v2データの移行は別途確認する | 既存データを引き継ぐ。元データを保持して変換を検証する |
| Dataset：HDF5／RLDS | 09でOFTローダへの接続に使用 | 専用実装を採用する。形式だけでなく単位・関節順序も照合する |

名称だけで選ばず、対象機体への対応と既存データ・コードの維持を先に確認します。未試験の経路を性能や保守性で劣ると断定しません。

## 3. 有効なセンサ拡張かを考える

センサを記録できること、学習入力として渡せること、モデルが利用してタスクを改善することは別です。まず「現在の観測では何が分からず、追加観測で何が分かるか」を書きます。

| 案 | 意味があるかを検討する問い | 設計・検証が必要な部分 |
|---|---|---|
| 追加RGBカメラ | 現在の視点で対象が遮蔽されるか。追加視点はその情報を得られるか | camera feature、モデルの視点数・前処理、推論時の同じ視点。不要な視点増加は負荷を増やす |
| 数値力覚 | 接触・荷重の状態が画像や関節値だけでは区別できないか | 軸・単位・ゼロ点・同期、数値表現、正規化、学習する重み。state連結は候補であり標準的効果を保証しない |
| 触覚画像 | 接触面や滑りを現在の観測では識別できないか | 画像の意味・前処理、encoder／融合、十分な対応データ。一般RGB入力へ載せるだけで触覚理解を保証しない |
| センサの履歴窓 | 現在の1値より、接触の時間変化が必要か | 時間窓・欠損・実効遅延、時系列表現、推論時の履歴保持 |

**入力できることと、意味のある拡張であることを分けます。** GelSight画像を通常RGBカメラの代わりに渡したり、力覚をstateの空き次元へ入れたりするだけでは、触覚・力覚を利用する学習経路の根拠になりません。少なくとも、既存観測で得られない情報、単位・時間変化を保持する表現、モデルへ届く処理、更新する重みと対応データを説明します。

標準入力と拡張案を混同しないため、固定版で次を確認します。

| 経路 | 実装を辿る入口 | 拡張案で確かめること |
|---|---|---|
| LeRobot版SmolVLA | `modeling_smolvla.py`の`prepare_state`・`prepare_images`・`state_proj`、configの`max_state_dim`・`train_state_proj` | 数値を追加する場合は前処理・正規化・paddingと学習対象を照合。画像の場合も、その情報に適した処理と学習経路を設計 |
| LeRobot版π₀.₅ | 08の保存preprocessorと`policies/pi05/`の入力処理 | stateの表現・tokenizerまで追う。SmolVLAのstate射影をそのまま使う前提にしない |
| OpenVLA-OFT | 09のRLDS builder・ALOHA patch、`proprio_projector`と画像処理 | この教材のproprioは14次元関節状態。力覚へ変更するならschema・次元・統計・射影・学習・推論を揃えて設計 |

これらは変更箇所の入口で、力覚・触覚への対応済みという意味ではありません。意味のある設計を説明できない案を、検証済みの接続手順として紹介しません。

これらは研究仮説の例です。03と06で確認したのは取得・保存・同期であり、力覚・触覚のモデル入力やタスク改善は未実証です。目的に対する必要性を確認してから、入力表現と比較実験を設計します。

## 4. 変更箇所を辿る

[03](03_architecture_and_extension.md)・付属sensor toolを取得と同期の入口とします。モデルへ進むときは、以下の各境界で情報が残っているかを確認します。

| 境界 | 具体的に調べる場所 | 確認するもの |
|---|---|---|
| Robotから収録へ | 固定版Robotの`observation_features`・`get_observation()`、またはsidecar | 名前・型・単位・時刻。sidecarは自動的にモデル入力にならない |
| Datasetからsampleへ | `meta/info.json`、`meta/stats.json`、`LeRobotDataset`、sidecarから派生sampleを作る処理 | feature・shape・episode対応・欠損・正規化統計 |
| sampleからbatchへ | processor、08の前後処理生成、モデルのinput_features | 未対応列を捨てていないか。既存の関節stateの順序・意味を維持する |
| batchからモデルへ | 固定版の`src/lerobot/policies/smolvla/`・`pi05/`等のconfigとmodeling実装 | 実際の入力経路、上限次元、学習対象、forwardとloss。個別案の互換性は未確認 |
| checkpointから実機へ | 前後処理の保存・再読込、実機観測の生成、公式推論経路 | 学習時と同じ特徴・単位・履歴、実行周期、出力制限・停止 |

ここでの場所は調査の入口です。センサを加えるための検証済みパッチではありません。研究として効果を示すなら、同じ条件でセンサ有無を比較し、成功率だけでなく失敗の種類・遅延・接触状態も評価します。まず記録の品質を確認し、その後にモデル融合と評価を設計します。
